It has three distinct phases:Phase 1 — Goal + Purpose RefinementThe user enters raw goal and raw purpose text. Bhudhi generates 3 refined options for each. The user selects and optionally edits their preferred option. The final edited text becomes the locked source of truth. Nothing proceeds without this step.Phase 2 — 20-Stage ValidationThe finalized goal and purpose feed a 20-stage validation pipeline powered by Bhudhi (Gemini 2.0 Flash with Google Search for market-facing stages). Each stage produces structured output stored on the validation record. The result is a complete reality check — not a report, a living workspace.Phase 3 — Editable Validation WorkspaceThe user sees all 20 stages as interactive cards. They can edit, add, remove, or refresh individual cards. Changes trigger partial recalculation of affected stages only. The user compares original vs updated. When satisfied, they finalize and select an execution path. The finalized package feeds the blueprint.CRITICAL LAW: Raw input is never the source of truth. Blueprint inherits goal_final and purpose_final. Blueprint does not reinterpret the idea. Blueprint executes the finalized truth.B — CONSTRAINTSREAD EVERY EXISTING FILE BEFORE WRITING ANYTHING.
