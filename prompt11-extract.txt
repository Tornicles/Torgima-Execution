WHAT THIS PROMPT BUILDS
Prompt 11 elevates EIS from a research tool into a full external intelligence layer. The Phase 1 EIS runs 5 web searches overnight and surfaces trending topics. Phase 11 EIS builds on that foundation to deliver: competitor activity tracking (what other creators/businesses in the user's niche published today), platform algorithm intelligence with confidence scoring, trend velocity analysis (rising vs peaking vs declining), opportunity window detection with time sensitivity flags, and narrative intelligence that understands public conversation shifts in the user's domain. When Prompt 11 is complete, Torgima tells users not just what is happening but what it means for their specific execution.

THREE LAWS RESTATEMENT
LAW 1: EIS intelligence is injected as context into task generation and validation. It never directly changes blueprint structure, signal values, or conditions. Market conditions inform Bhudhi â€” Bhudhi informs task generation â€” Control Engine governs what is actually generated.
LAW 2: Competitor intelligence is surfaced as awareness, not direction. EIS never instructs the user to copy a competitor or pivot based on competitor success alone. It provides context that the Strategy Agent reads when generating direction analysis.
LAW 3: EIS outputs are marked with a confidenceTier and researchMethod. WEB_SEARCH results are more trusted than CACHED, which are more trusted than FALLBACK. The user interface shows 'Intelligence based on recent research' vs 'Intelligence based on cached data' appropriately.

PART 3 â€” FULL EIS NIGHTLY RESEARCH ARCHITECTURE
The complete nightly EIS research suite. 9 modules running in coordinated sequence, respecting rate limits, building on each other's outputs.
// OvernightWorker.ts â€” STEP 02 UPGRADED TO FULL 9-MODULE EIS SUITE

export async function runFullEISNightlySuite(
  userId: string,
  context: OvernightContext
): Promise<FullEISBriefing> {
  // Check rate limit first
  const rateCheck = await canRunResearch(userId, context.domain)
  if (!rateCheck.allowed) {
    return await getLatestBriefing(userId, context.domain) || buildFallbackBriefing(context)
  }

  // MODULE 1: Core Research (from Prompt 8 â€” 5 searches)
  const coreResearch = await runCoreResearch(userId, context)

  // MODULE 2: Competitor Intelligence
  const competitors = await runCompetitorIntelligence(userId, {
    domain: context.domain,
    niche: context.niche,
    userFollowerTier: context.followerTier,
  })

  // MODULE 3: Trend Velocity (uses coreResearch trends as input)
  const trendVelocity = await runTrendVelocityAnalysis(userId, {
    domain: context.domain,
    niche: context.niche,
    existingTrends: coreResearch.trendingTopics,
  })

  // MODULE 4: Narrative Intelligence
  const narrative = await runNarrativeIntelligence(userId, {
    domain: context.domain,
    niche: context.niche,
  })

  // MODULE 5: Platform Algorithm Scan
  const platformSignals = await scanPlatformAlgorithms(
    context.activePlatforms,
    context.domain,
    context.niche
  )

  // MODULE 6: Opportunity Window Synthesis
  // Cross-references: emerging trends + competitor gaps + narrative angles
  // Produces: ranked opportunity list with time windows
  const opportunities = await synthesizeOpportunityWindows({
    trends: trendVelocity,
    competitors,
    narrative,
    currentBlueprintPhase: context.blueprintPhase,
  })

  // MODULE 7: Daily Recommendation Generation
  // One specific action for today based on all intelligence
  const todayRecommendation = await generateTodayRecommendation({
    opportunities,
    activeOrder: context.preGeneratedOrder,
    condition: context.condition,
  })

  // MODULE 8: Knowledge Library Updates
  // Update KnowledgePackage records with fresh intelligence
  await updateKnowledgeLibrary(userId, context.domain, {
    trends: trendVelocity,
    narrative,
    platformSignals,
  })

  // MODULE 9: Full Briefing Assembly
  return assembleFull EISBriefing({
    core: coreResearch,
    competitors,
    trends: trendVelocity,
    narrative,
    platforms: platformSignals,
    opportunities,
    todayRecommendation,
  })
}

PART 4 â€” EIS INTELLIGENCE INJECTION INTO TORGIMA
EIS intelligence is injected at 4 points in the execution system. Each injection is context-specific and filtered through Adaptive Communication Engine.
INJECTION POINT 1
Task Generation
EIS competitor and trend data injected into task.draft.v3 context. Tasks framed around what is working in the market right now, not generic instructions. Example: task instruction includes 'Trending this week: goalkeeper POV clips â€” consider this angle for your Create task.'

INJECTION POINT 2
Goal Validation
EIS demand signals injected into goal.feasibility.v1. Feasibility score reflects current market conditions, not just user capability. A goal in a declining niche scores lower than the same goal in an emerging niche.

INJECTION POINT 3
Direction Analysis
EIS competitive landscape injected into direction.analysis.v1. Strategy Agent's proceed/adjust/pivot recommendation reflects market reality. User is told if competitors are already dominating their planned approach.

INJECTION POINT 4
Morning Report
Full EIS briefing surfaced on dashboard. Competitor activity, trend velocity, platform signals, narrative angle, and today's opportunity all rendered in the Intelligence Report screen.
