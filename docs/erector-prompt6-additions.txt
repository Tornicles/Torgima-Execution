Addition 1 — Validate route group layout guard
Create app/(validation)/layout.tsx if it does not exist. This layout must enforce that a blueprintDraftId exists in the URL params or session before rendering any validation screen. If no draft is found, redirect to /onboarding/goal.
// app/(validation)/layout.tsx
export default async function ValidationLayout({ children, params }) {
  const session = await getServerSession();
  if (!session?.user?.id) redirect(&apos;/login&apos;);

  const draft = await prisma.blueprint.findFirst({
    where: { user_id: session.user.id, status: { in: [&apos;draft&apos;,&apos;validating&apos;] } },
    select: { id: true, status: true }
  });

  if (!draft) redirect(&apos;/onboarding/goal&apos;);

  return <>{children}</>;
}

Addition 2 — Dashboard: Archetype intelligence panel
Add an Archetype Intelligence panel to the dashboard. This panel shows the user the civilisation context their execution is running inside. It is read-only, informational, and updates never — it is locked at blueprint launch.
Panel content:

Addition 4 — Navigation: post-launch redirect
In the Blueprint Level Selection screen (last Erector screen), the &apos;Launch Blueprint&apos; button calls POST /api/v1/blueprints/launch. After a 200 response, the client must redirect to /dashboard. Update the success handler:
const handleLaunch = async () => {
  setLaunching(true);
  const res = await fetch(&apos;/api/v1/blueprints/launch&apos;, {
    method: &apos;POST&apos;,
    body: JSON.stringify({ blueprint_draft_id: draftId, selected_path: selectedPath })
  });
  if (res.ok) {
    router.push(&apos;/dashboard&apos;);
  } else {
    const err = await res.json();
    setError(err.message);
    setLaunching(false);
  }
};
GATE: Click Launch Blueprint → POST succeeds → browser navigates to /dashboard → Execution Context panel visible → first smoke test task visible with &apos;Smoke Test — Week 1&apos; indicator.
