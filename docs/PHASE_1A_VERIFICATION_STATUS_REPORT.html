Why Part 3.4 fails

The runbook requires zero matches for internal terms in artifacts/torgima/src/components/:

Root causes:

  • Bhudhi product surfaces — The Bhudhi Hub, dashboard, and universal sections intentionally display “Bhudhi” as the product name (~20 files under components/bhudhi/).
  • Validation verdict UI — VerdictPanel.tsx compares raw enum values PROCEED, PIVOT instead of customer labels from language-map.ts.
  • Condition keys in logic — SignalsDashboardView.tsx, LaunchNothingnessDashboard.tsx, ConditionStatusPanel.tsx use internal condition keys like nothingness for styling/routing (some already map labels via language-map for display).
  • Enforcement package data — DashboardPanels.tsx reads state.enforcement and renders allowed/blocked actions using internal field names.
  • Onboarding copy — ErectorIntakeFlow.tsx and validation dashboards reference Bhudhi and internal validation language.

Fix required: Migrate all customer-visible strings to artifacts/torgima/src/lib/language-map.ts; keep internal keys only in non-UI logic or map at render time. Bhudhi-branded pages may need a runbook exception or a renamed customer label (e.g. “Project Intelligence”).
