Erector â†’ Execution Bridge
Connecting Validation Intelligence to the Live Execution Loop

A â€” PURPOSE OF THIS PROMPT
The Erector (Prompt 3) ends at blueprint launch. The execution loop (Prompt 5 onward) begins at task generation. This prompt builds the bridge between them. Without this bridge, the archetype intelligence gathered during validation is collected but never used. The first week plan is generated but never seeded. The reality score is stored but the execution engine never reads it.
This prompt has one job: make the Erector's output a living, active part of every execution decision from the moment the blueprint launches.

C â€” CORE LAWS
EXTEND ONLY. launchBlueprint() gets new logic added inside the existing transaction. Nothing is removed.
ARCHETYPE NEVER OVERRIDES CONDITION. Archetype multipliers adjust task count ranges and pace calculations. They never set a condition directly. Condition is always owned by the Signal Engine.
FIRST WEEK TASKS ARE SMOKE TESTS. They seed the task queue with reality-checking actions before the normal execution loop takes over. They do not replace the normal loop.
ALL NEW BHUDHI CALLS FOLLOW THE EXISTING PATTERN. Registered in TriggerRouter, Zod schema, BhudhiLog write, deterministic fallback. No exceptions.
