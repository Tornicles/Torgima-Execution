Addition 2 — Dead letter queue handlers for Erector failures
Erector failures have different recovery logic from execution loop failures. A failed validation can be retried. A failed blueprint launch needs a specific repair path. Add these dead letter queue cases to the existing DLQ handler:
// Add to existing dead letter queue handler:
case &apos;erector_validation_started&apos;:
case &apos;erector_engine_completed&apos;: {
  // Validation can be retried — reset validation_stage to &apos;pending&apos; and allow re-run
  await prisma.validation.updateMany({
    where: { id: payload.validation_id },
    data: { validation_stage: &apos;failed&apos;, updated_at: new Date() }
  });
  // User will see &apos;Validation failed — retry available&apos; state on validation screen
  break;
}

case &apos;erector_blueprint_launched&apos;: {
  // Launch failed after validation — critical. Set blueprint back to path_selection.
  await prisma.blueprint.updateMany({
    where: { id: payload.blueprint_id },
    data: { status: &apos;path_selection&apos;, active: false }
  });
  await emitEvent({ event_type: &apos;blueprint_launch_failed&apos;, ...payload });
  break;
}

Addition 3 — System health check: validation pipeline
Add a validation pipeline health check to the SystemHealthWorker. This check runs every 5 minutes alongside existing health checks and verifies the Erector pipeline is not stuck.
// Add to SystemHealthWorker checks:
async function checkValidationPipeline() {
  // Check 1: No validation stuck in &apos;running&apos; for more than 5 minutes
  const stuckValidations = await prisma.validation.count({
    where: {
      validation_stage: &apos;running&apos;,
      updated_at: { lt: new Date(Date.now() - 5 * 60 * 1000) }
    }
  });

  // Check 2: No blueprint in &apos;path_selection&apos; for more than 48 hours
  const abandonedValidations = await prisma.blueprint.count({
    where: {
      status: &apos;path_selection&apos;,
      updated_at: { lt: new Date(Date.now() - 48 * 60 * 60 * 1000) }
    }
  });

  await prisma.systemHealthLog.create({ data: {
    check_type: &apos;validation_pipeline&apos;,
    status:     stuckValidations > 0 ? &apos;warn&apos; : &apos;ok&apos;,
    score:      stuckValidations === 0 ? 10 : 5,
    details_json: { stuckValidations, abandonedValidations }
  }});
}
