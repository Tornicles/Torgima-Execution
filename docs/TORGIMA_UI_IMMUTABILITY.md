# TORGIMA UI Immutability & Design Protection System

**Master instruction** for Cursor, Claude, Lovable, Bolt, Windsurf, or any AI builder working on TORGIMA.

## Primary directive

The current dashboard designs are **approved production UI**. Build functionality, intelligence, data flow, backend, APIs, synchronization, calculations, automation, and AI behavior **without** changing visual structure.

The UI is **not** to be redesigned, reimagined, optimized, modernized, improved, simplified, rearranged, or replaced.

**Only data changes. Never layout, structure, styling, navigation, or visual hierarchy.**

---

## Immutable design rule

Treat every dashboard as a **fixed shell** (a television: only the picture changes).

### Sidebar — locked

Do not add, remove, reorder, or resize menu items; do not change icons, spacing, or navigation structure.

### Header — locked

Do not move profile, notifications, or date selectors; do not add/remove controls or change dimensions.

### Cards — locked containers

Do not change size, position, spacing; do not merge, split, or convert cards/tabs. Only contents update.

### Dashboard sections — locked positions

Do not move, rearrange, collapse, expand, or invent new layouts.

### Typography & colors — frozen

Do not change fonts, weights, families, heading structure, theme, gradients, or brand palette.

---

## Allowed changes

- **Dynamic text**: goals, plans, phases, conditions, signals, blueprints, tasks, feedback, validation, competitors, risks, Bhudhi copy, etc.
- **Dynamic metrics**: scores, progress, rates, levels, community stats, etc.
- **Dynamic charts**: values, labels, dates, trends, datasets — **not** position, size, design, or structure.
- **Dynamic tables/lists**: row/item data — **not** table/list chrome.

---

## Screen protection

| Screen | Lock (layout); allow data only |
|--------|--------------------------------|
| **Home** | Blueprint progress, orders, signal overview, recent activity, timeline, upcoming milestones |
| **Bhudhi** | Core panel, explanation panels, questions, system activity, information sources |
| **Erector** | Validation, simulator, industry, learning cards; recent validation lists |
| **Validation results** | Reality score, verdict, competitors, risks, opportunities, success plan |
| **Signals** | Signal graph, condition card, competitors, milestones, Bhudhi section |
| **Project** | Signal trend, condition, health, milestones, competitors, key milestones |
| **Community** | Discussions, events, contributors, groups |
| **Academy** | Learning progress, course cards, categories, recommendations, calendar |
| **Settings** | Entire page layout; user/account fields only |
| **Messages** | Conversation list, chat window, input area; message body only |

---

## Development rule

1. Find existing component.
2. Inject functionality.
3. Preserve design.
4. Verify no visual modifications.
5. Deploy.

**Extend existing components. Never replace shells.**

---

## AI behavior rule

Refuse requests to improve, redesign, modernize, optimize layout, add UX polish, or restructure navigation.

**Standard response:**

> TORGIMA UI is locked. Only functionality, intelligence, synchronization, calculations, automation, and data updates are allowed.

---

## Two layers

| Layer | Role |
|-------|------|
| **Layer 1 — Static visual** | Permanent, frozen, protected |
| **Layer 2 — Dynamic intelligence** | Bhudhi, signals, conditions, validation, blueprints, projects, tasks, feedback, reports, community, academy — evolves forever |

Build everything in Layer 2 while preserving Layer 1 exactly as approved. Follow the TORGIMA specification for screen architecture and execution flow.
